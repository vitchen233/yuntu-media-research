# 浏览器、登录会话与宿主适配

单条页面核对使用的是宿主 Agent 的浏览器能力，不是 RedFox。RedFox 可以补批量作品、账号和互动字段，但不能证明 Agent 已经看到页面中的完整画面、字幕、评论或登录后内容。

## 每次单条任务前先判断

按顺序检查并记录：

1. `browser_channel`：系统 Chrome 控制插件/MCP、宿主内置浏览器、其他浏览器或不可用。
2. `session_mode`：复用用户现有 Chrome 登录、宿主独立会话、无需登录或未知。
3. `login_required`：目标页面是否要求登录后才能继续查看。
4. `verification_status`：`verified`、`partial`、`login-blocked`或`unverified`。

这些字段进入研究简报、来源清单和报告方法说明。不能只写“已使用浏览器”。

## 四条执行路径

### A. 复用用户已经登录的 Chrome

当宿主提供 Chrome 控制插件、Chrome MCP 或等价能力，并且用户希望使用自己已登录的平台账号时优先采用。Codex 可以调用当前环境可用的 Chrome 控制能力；工具名称不固定，也不能假设每台电脑都已安装。

1. 让用户自行打开 Chrome、进入目标平台并完成登录。
2. Agent 只接管用户授权的目标标签页，先确认当前域名和账号状态。
3. 只执行当前研究所需的查看、滚动、搜索和打开作品。
4. 不读取、导出或保存 Cookie、Token、浏览器档案和密码。

### B. 使用宿主内置浏览器的独立会话

公开页面可直接核对。页面要求登录时，明确告诉用户这是与日常 Chrome 分开的会话，让用户在该浏览器中自行登录；不得要求用户把密码、验证码或 Cookie 发到聊天中。

宿主如果能够持久保存该会话，可以在用户确认后继续使用；不能持久保存时必须说明下次可能需要重新登录。

### C. 当前宿主无法复用登录会话

WorkBuddy、Claude Code或其他Agent的浏览器实现可能随版本、插件和系统不同。先检查它是否支持系统 Chrome 控制、浏览器扩展、MCP 或持久化内置浏览器：

- 支持时，按该宿主实际能力连接，不照搬Codex工具名。
- 只有隔离浏览器时，按路径B处理。
- 页面必须登录但当前会话无法完成时，保存`login-blocked`，再选择RedFox字段补充或停止单条深拆。
- 不要求用户导出浏览器Cookie，也不把“RedFox有作品字段”写成“页面已核对”。

### D. 没有可用浏览器

仍可完成RedFox批量选题或账号分析，但报告必须标记`unverified`，删除依赖画面、完整字幕、可见评论和页面交互的结论。内容结构拆解如果缺少足够页面或转写证据，应停止并说明缺口。

## 登录与权限边界

- 登录动作由用户亲自完成，Agent不得索取密码、短信验证码或二次验证代码。
- 不绕过登录、验证码、风控、地区限制、DRM或付费墙。
- 复用Chrome登录不等于授权访问所有标签页，只操作当前任务所需页面。
- 不在报告、日志、截图或公开演示中暴露昵称、私信、收藏、历史记录等无关个人信息。
- 如果平台出现发布、关注、点赞、评论、私信或购买等写操作，默认停止并等待用户明确确认。

## 给用户的简短说明

```text
这一步核对的是单条页面，使用宿主Agent的浏览器，不会消耗RedFox积分。当前页面需要登录。我可以优先连接你已经登录的Chrome；请你自行完成登录并停留在目标页面，我不会读取或保存密码、Cookie和其他标签页内容。如果当前Agent不能复用Chrome，我会明确标记登录受阻，再决定改用独立浏览器、RedFox字段补充或停止深拆。
```
