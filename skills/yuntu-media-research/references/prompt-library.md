# 可直接复制的任务提示词

以下提示词不绑定Codex、WorkBuddy或其他宿主。只替换`{{ }}`中的内容。新电脑建议按`安装 → 初始化 → 单项研究`执行；已经配置过的电脑直接从具体任务开始。

## 0. 新电脑安装

把下面整段发给Codex、WorkBuddy、Claude Code或其他支持`SKILL.md`的Agent：

```text
请从下面的公开GitHub仓库安装 yuntu-media-research：
https://github.com/vitchen233/yuntu-media-research

请先读取仓库README、THIRD_PARTY_NOTICES和Skill正文，确认安装目标是当前Agent的标准Skills目录。
然后使用仓库提供的install.py完成安装，并安装requirements.txt中的RedFox SDK依赖；不要把Skill复制进我当前的内容项目，也不要安装FunASR或下载模型。
安装后运行Skill自带的doctor.py --json，只告诉我各项是否就绪，不得显示任何API Key。
如果当前Agent需要重新加载或重启才能识别新Skill，请明确告诉我下一步怎么做，不要假装已经加载成功。
完成后给我一条可以直接发送的“首次初始化”提示词。
```

## 1. 首次初始化与配置

```text
第一次使用 yuntu-media-research。
请开始首次初始化，不要直接运行研究任务。
第一步，先用一份简短问卷引导我填写长期稳定的创作者信息：我的身份、赛道、主要平台、目标受众及其问题、内容目标、优先工具、交付物和内容边界。
把这些信息保存到用户级creator-profile.json，不要写进Skill源码或公开仓库。以后研究时，本次任务的明确输入优先于这份档案。
第二步，再检查Python、RedFox SDK和API Key。不要让我在聊天里粘贴API Key，也不要显示密钥内容；需要Key时引导我在本机隐藏输入。
两步都完成后，告诉我可以直接做哪三类研究任务，以及怎样根据研究结果继续生成初稿。
```

## 2. 根据主题找近3天可拍选题

```text
调用 yuntu-media-research，运行 topic-research。
我要研究的主题是：{{例：AI做自媒体 / Vibe Coding / DeepSeek新工具}}。
我的赛道是：{{例：AI提效自媒体}}。
我的观众是：{{具体人群}}。
我想优先使用的工具是：{{Codex / WorkBuddy / 其他}}。
目标是：{{涨粉 / 搜索流量 / 开源Skill领取}}。
平台是：{{抖音 / 小红书 / B站 / 视频号}}。

请由AI自动采集近3天的公开作品，不要让我先准备链接或表格。
先区分“很多创作者在讲”和“观众真的在问”，再给采集计划、预计请求数与RedFox费用；等待我确认付费调用后执行。
最终只推荐3条能够真实录屏的选题，每条包含：
- 目标人群与具体任务；
- 开头先展示什么结果；
- AI如何采集原始材料；
- 实际要录制哪些操作；
- 1至3条可打开的对标链接；
- 可交付的Skill、源码、模板或文档钩子；
- 证据、样本限制和拍摄准备度。

保存原始来源和独立HTML报告，最后告诉我文件路径。
```

## 3. 拆解作者主页

```text
调用 yuntu-media-research，运行 creator-analysis。
分析对象：{{博主名称或公开主页链接}}。
我的赛道是：{{你的赛道}}；我想借鉴的是：{{选题 / 钩子 / 教学方式 / 交付钩子}}。

请由AI自动采集该账号的最新作品和高表现作品，建立账号内基线，不要只挑几条凭感觉总结。
报告至少包含：
- 账号定位、核心人群、内容承诺与转化资产；
- 内容支柱、发布节奏和时长分布；
- 最新样本与高表现样本的点赞、评论、收藏、转发基线；
- 钩子类型、代表标题、内容方法和证明方式；
- 从停留到领取、安装或关注的转化路径；
- 收藏/点赞与转发/点赞图表；
- 3条高表现作品从开头钩子、内容方法、证明到CTA的逐条拆解；
- 我可以借鉴和不应照搬的部分。

为钩子和方法标明证据级别。只有标题时不要写成已核验逐字稿。
保存原始数据、报告JSON和独立HTML，最后告诉我文件路径。
```

## 4. 拆解单条视频

```text
调用 yuntu-media-research，运行 content-structure-analysis。
公开作品链接：{{抖音 / 小红书 / B站 / 视频号链接}}。
我准备制作的内容是：{{你的主题}}。

请先用浏览器核对页面、章节、可见字幕和画面。确实需要完整文案时，先检测本机FunASR；缺少时先征得我同意，再从官方渠道安装或拉取到Skill之外的隔离环境。只有本地方案不可用时，才告诉我RedFox转写的预计费用并等待确认。完整机器转写可以保存在本地研究目录供分析，但不要在公开HTML里全文转载。
按时间顺序拆解：
- 开头承诺和第一份证明；
- 每个段落的话语作用与观众所得；
- A-roll、实际录屏、结果页与图表的使用比例；
- 注意力曲线与信息密度变化；
- 口播段落对应什么画面，单个画面建议最长停留多久；
- 从结果、过程到交付物的证明链；
- 可复用结构与依赖原作者人格、数据或夸张承诺的部分。

不要复制原句或输出完整逐字稿。
最后生成我的改写方向，并保存带时间轴、图表和画面对应表的独立HTML报告。
```

## 5. 从主页与单条结果提炼可复用结构

```text
调用 yuntu-media-research。
主页分析目录：{{creator-analysis真实目录；没有可留空}}。
单条拆解目录：{{content-structure-analysis真实目录}}。
我准备制作的主题是：{{你的主题}}。
我的目标受众是：{{具体人群}}。

请优先读取这两个目录中已经保存的原始数据、来源清单、报告JSON和转写结果；证据足够时不要重复调用RedFox。
把对标内容提炼成一套“可以复用但不会抄袭”的内容结构，至少包括：
- 适用人群、任务和使用边界；
- 前5秒如何展示完成结果，第一份证明出现在哪里；
- 各段的观众问题、话语作用、实际画面和证明材料；
- 信息密度、注意力曲线、A-roll / 录屏 / 结果页的建议比例；
- 哪些结构来自多条样本，哪些只来自单条推断；
- 依赖原作者人格、数据和夸张承诺而不能照搬的部分；
- 改成我的主题后，推荐标题、开头、内容顺序和交付钩子。

按现有`content-structure-analysis`报告合同生成`report.json`和一份图表充实、可双击打开的独立HTML报告，并额外保存`reusable_structure.md`。每个判断都回指来源；没有证据的地方标明推断，不要生成完整口播稿。
```

## 6. 一次生成三份报告（演示模式）

```text
调用 yuntu-media-research，运行完整研究链。
我的赛道是：{{赛道}}；观众是：{{人群}}；目标是：{{涨粉 / 交付物领取}}。

第一步，先用 topic-research 自动采集近3天公开内容，生成3条候选和选题HTML。
第二步，选择最有代表性的一位公开博主，运行 creator-analysis，生成完整账号HTML。
第三步，从该账号选择一条可打开的高表现作品，运行 content-structure-analysis，生成单条结构HTML。

前一步的选中对象必须成为下一步输入，不要临时更换方向。
三份报告都使用真实公开数据、可打开来源、明确时间和样本限制，并生成一个统一HTML入口。
```

## 7. 新电脑完整演示

安装和初始化已经完成后，可以用下面这条连续展示Skill的核心能力：

```text
调用 yuntu-media-research，运行一轮可录屏的完整研究演示。
研究主题：{{主题}}；平台：{{平台}}；时间窗：近3天；我的受众：{{具体人群}}。

第一步，先给出采集计划、预计RedFox请求数和费用，等待我确认后再开始。
第二步，运行topic-research，自动寻找公开作品并生成3条候选选题与选题HTML。
第三步，从真实样本中选择一位最有分析价值的作者，运行creator-analysis并生成作者主页HTML。
第四步，从该作者选择一条可打开的高表现作品，运行content-structure-analysis。先用浏览器核对；需要完整文案时优先调用本地FunASR，任何安装、模型下载或付费转写都先征得我同意。
第五步，基于前三步已经保存的数据提炼可复用内容结构，不重复付费采集，生成结构报告HTML和统一报告入口。

全程保存原始数据、来源URL、费用记录、失败回退和报告JSON。每完成一步先告诉我产物路径，再继续下一步；不要编造数据，也不要把单条推断写成普遍规律。
```

## 8. 同一任务比较两个智能体

```text
调用 yuntu-media-research。
这是一次跨宿主对比实验，请严格执行以下固定任务，不自行扩大范围：
平台：{{抖音}}；时间窗：{{近3天}}；赛道：{{AI提效自媒体}}；查询词：{{词1、词2、词3}}。
只运行 topic-research，采集后生成3条候选和HTML报告。
额外记录：总耗时、API请求数、人工接管次数、原始样本数、排除样本数、可打开来源数、最终文件路径。
不读取另一个智能体的产物，保证独立执行。
```

## 9. 根据已完成的研究生成短视频初稿

```text
调用 yuntu-media-research，运行 draft-from-research。
我已经选中的题目是：{{候选题标题}}。
研究任务目录是：{{research-output中的真实路径}}。

请只使用该目录中的来源清单、报告、代表作品、失败记录和真实交付物生成初稿，不要重新虚构材料。
初稿面向我在creator-profile.json中保存的目标受众；本次任务明确修改的信息优先。

写作采用适合任务型短教学的结构：
1. 开头先出现真实完成结果，并点明和哪类人有关；
2. 说明观众原来需要手工完成的具体动作；
3. 说明AI如何自动取得原始材料；
4. 用连续升级的步骤完成任务，每一步都出现新的可见证明；
5. 说明哪些判断仍需要人完成，以及失败时怎样接管；
6. 结尾交付真实存在的Skill、源码、模板或文档。

不要复制任何对标作者的原句、人格、独特命名和效果承诺，不要编造播放量、涨粉或节省时间。
输出selected_topic.md、draft.md、draft_source_map.json和audit.md，并运行validate_draft.py检查。
先给我初稿，不写A/B-roll、分镜、字幕动画或剪辑包装。
```
