# 可直接复制的任务提示词

以下提示词不绑定Codex、WorkBuddy或其他宿主。安装Skill后，只替换`{{ }}`中的内容。

## 0. 首次配置

```text
第一次使用 yuntu-media-research。
请先自动检查我的Python、RedFox SDK、API Key和创作者研究档案是否就绪。
如果缺少配置，一步一步引导我；不要让我在聊天里粘贴API Key，也不要显示密钥内容。
技术配置完成后，请继续引导我填写长期稳定的创作者信息：我的身份、赛道、主要平台、目标受众、受众问题、内容目标、优先工具、交付物和内容边界。
把这些信息保存到用户级creator-profile.json，不要写进Skill源码或公开仓库。以后研究时，本次任务的明确输入优先于这份档案。
配置通过后，告诉我可以直接做哪三类任务。
```

## 1. 找近3天可拍选题

```text
调用 yuntu-media-research，运行 topic-research。
我的赛道是：{{例：AI提效自媒体 / Vibe Coding}}。
我的观众是：{{具体人群}}。
我想优先使用的工具是：{{Codex / WorkBuddy / 其他}}。
目标是：{{涨粉 / 搜索流量 / 开源Skill领取}}。

请由AI自动采集近3天的公开作品，不要让我先准备链接或表格。
先给采集计划和预计请求数，然后执行。
最终只推荐3条能够真实录屏的选题，每条包含：
- 目标人群与具体任务；
- 开头先展示什么结果；
- AI如何采集原始材料；
- 实际要录制哪些操作；
- 1至3条可打开的对标链接；
- 可交付的Skill、源码、模板或文档钩子；
- 证据、样本限制和拍摄准备度。

保存原始来源和独立HTML报告，最后告诉我文件路径。
```

## 2. 拆解一个博主或账号

```text
调用 yuntu-media-research，运行 creator-analysis。
分析对象：{{博主名称或公开主页链接}}。
我的赛道是：{{你的赛道}}；我想借鉴的是：{{选题 / 钩子 / 教学方式 / 交付钩子}}。

请由AI自动采集该账号的最新作品和高表现作品，建立账号内基线，不要只挑几条凭感觉总结。
报告至少包含：
- 账号定位、核心人群、内容承诺与转化资产；
- 内容支柱、发布节奏和时长分布；
- 最新样本与高表现样本的点赞、评论、收藏、转发基线；
- 钩子类型、代表标题、内容方法和证明方式；
- 从停留到领取、安装或关注的转化路径；
- 收藏/点赞与转发/点赞图表；
- 3条高表现作品从开头钩子、内容方法、证明到CTA的逐条拆解；
- 我可以借鉴和不应照搬的部分。

为钩子和方法标明证据级别。只有标题时不要写成已核验逐字稿。
保存原始数据、报告JSON和独立HTML，最后告诉我文件路径。
```

## 3. 拆解一条视频的钩子、方法和画面

```text
调用 yuntu-media-research，运行 content-structure-analysis。
公开作品链接：{{抖音 / 小红书 / B站 / 视频号链接}}。
我准备制作的内容是：{{你的主题}}。

请优先取得作品详情或视频转写，有浏览器时核对页面、章节和可见画面。
按时间顺序拆解：
- 开头承诺和第一份证明；
- 每个段落的话语作用与观众所得；
- A-roll、实际录屏、结果页与图表的使用比例；
- 注意力曲线与信息密度变化；
- 口播段落对应什么画面，单个画面建议最长停留多久；
- 从结果、过程到交付物的证明链；
- 可复用结构与依赖原作者人格、数据或夸张承诺的部分。

不要复制原句或输出完整逐字稿。
最后生成我的改写方向，并保存带时间轴、图表和画面对应表的独立HTML报告。
```

## 4. 一次生成三份报告（演示模式）

```text
调用 yuntu-media-research，运行完整研究链。
我的赛道是：{{赛道}}；观众是：{{人群}}；目标是：{{涨粉 / 交付物领取}}。

第一步，先用 topic-research 自动采集近3天公开内容，生成3条候选和选题HTML。
第二步，选择最有代表性的一位公开博主，运行 creator-analysis，生成完整账号HTML。
第三步，从该账号选择一条可打开的高表现作品，运行 content-structure-analysis，生成单条结构HTML。

前一步的选中对象必须成为下一步输入，不要临时更换方向。
三份报告都使用真实公开数据、可打开来源、明确时间和样本限制，并生成一个统一HTML入口。
```

## 5. 同一任务比较两个智能体

```text
调用 yuntu-media-research。
这是一次跨宿主对比实验，请严格执行以下固定任务，不自行扩大范围：
平台：{{抖音}}；时间窗：{{近3天}}；赛道：{{AI提效自媒体}}；查询词：{{词1、词2、词3}}。
只运行 topic-research，采集后生成3条候选和HTML报告。
额外记录：总耗时、API请求数、人工接管次数、原始样本数、排除样本数、可打开来源数、最终文件路径。
不读取另一个智能体的产物，保证独立执行。
```

## 6. 根据已完成的研究生成短视频初稿

```text
调用 yuntu-media-research，运行 draft-from-research。
我已经选中的题目是：{{候选题标题}}。
研究任务目录是：{{research-output中的真实路径}}。

请只使用该目录中的来源清单、报告、代表作品、失败记录和真实交付物生成初稿，不要重新虚构材料。
初稿面向我在creator-profile.json中保存的目标受众；本次任务明确修改的信息优先。

写作采用适合任务型短教学的结构：
1. 开头先出现真实完成结果，并点明和哪类人有关；
2. 说明观众原来需要手工完成的具体动作；
3. 说明AI如何自动取得原始材料；
4. 用连续升级的步骤完成任务，每一步都出现新的可见证明；
5. 说明哪些判断仍需要人完成，以及失败时怎样接管；
6. 结尾交付真实存在的Skill、源码、模板或文档。

不要复制任何对标作者的原句、人格、独特命名和效果承诺，不要编造播放量、涨粉或节省时间。
输出selected_topic.md、draft.md、draft_source_map.json和audit.md，并运行validate_draft.py检查。
先给我初稿，不写A/B-roll、分镜、字幕动画或剪辑包装。
```
